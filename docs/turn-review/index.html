「退回」本来该是什么

不满意这一轮时，在改动上指出哪里不对，一键把这些意见发回给同一个 Agent，让它接着改。这是演示：代码和 Agent 的回复都是写死的假数据，没有连接任何真实 Agent，也没有改任何文件。

和你现在的做法差在哪

现在：在终端里打字这个功能：批注后退回
说清楚位置要自己写文件名和行号，或者描述一下点那一行就写，位置和原代码自动带上
看改动只有文件列表和增删行数，diff 要去别处看在 Mooring 里直接看这一轮的 diff
多条意见边看边记，最后一次打完攒着，最后一起发
验收标准没达标的要自己说没勾上的自动带进消息
代价没有，几句话就说完多一个页面要点；小问题反而更慢

要决定的事

值不值得做这一页。判断方法很简单：回想最近几次验收，你是不是常常要对着代码说「这一行不对」。

  • 值得做：经常要指到具体的行，或者一轮要提好几条意见。
  • 不做：你平时主要看运行结果、看界面，一句话就能说清。那直接在终端打字更快，按钮删掉就是对的。

演示把稿子里分开的「退回」和「发回 Claude Code」合成了一个按钮；稿子本身没有写清退回做什么，这是这次的理解，不是原定方案。
