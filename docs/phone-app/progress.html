定下来的事

  • 手机只做聊天，不做终端。工具调用可以点开看，终端只看最后几行。
  • 额度按电脑分开、不相加；手机只从配对的电脑取。
  • Markdown 用 remark 解析加自绘组件。在 OPPO 上和原生库实测对比后选的，理由见 markdown.md。
  • 不做：审批失效时间和「推送 6 个提交」这类后果说明（电脑拿不到可靠数据）；金额（没有可信价格表）；一键回复（要猜 Agent 的话）。
  • 上线流程：本地 main 只跟随远端。分支变基后开 PR 并设自动合并，CI 通过才进 main（11-06 起直接推会被拒）。打包也从 origin/main 来。
  • 全部放行：手机上可以切，切之前二次确认，开了 Face ID 再验证；Claude 启动时没带跳过权限的参数就不列这一档。

要留意的风险

  • Codex 可能要你重新登录。测试时把 ~/.codex/auth.json 复制到临时目录用过 7 次（副本已删），如果令牌被刷新，真实登录可能失效。
  • 有个测试在高负载下失败过。a_dialog_gone_from_the_screen_is_settled_by_claude_official_status 在负载 50 以上时失败，低负载通过。包含这些提交的 main 后来 CI 通过（4b2c66c），但 CI 不是高负载，也没在高负载下对比过旧版本。
  • 打码不是万无一失。工具输出发送前在电脑上打码，但名字里不带关键词的密钥认不出。
  • 第一次点允许没反应的现象修了三个可能原因，都是推断。再遇到请告诉我。
  • 手机测试用例依赖顺序。hub 的 3 个测试在随机顺序下失败，9444c03 上同样存在，这轮没修。CI 用的固定顺序不受影响。
  • 电脑卡死。11-05 拔电跑高负载卡死过一次。重任务要低优先级、一次一个、插着电。

怎么操作

以后接手的人或 Agent 照这里做。凭据不写在这里。

换电脑上的 Mooring（从 origin/main 的干净工作区）

export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
export LIBGHOSTTY_VT_SYS_OPTIMIZE=ReleaseFast
nice -n 10 cargo build --release -p fibo-app -p fibo-host
python3 package-macos.py --output ~/Desktop/code/AI/tools/mooring/target/bundle-here/Mooring.app
osascript -e 'tell application id "local.mooring.workbench" to quit'
env -i HOME=$HOME USER=$USER LOGNAME=$USER SHELL=/bin/zsh TMPDIR=$TMPDIR LANG=en_US.UTF-8 \
  PATH=/usr/bin:/bin:/usr/sbin:/sbin open <bundle> --args --runtime ~/.local/share/keepline-workbench

编手机包并安装

cd mobile && bun install --frozen-lockfile
CI=1 bunx expo prebuild -p android --no-install
# android/local.properties 写 sdk.dir；gradle.properties 末尾加 Clash 7897 代理
cd android
./gradlew :app:createBundleReleaseJsAndAssets --rerun
./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a
~/Library/Android/sdk/platform-tools/adb install -r app/build/outputs/apk/release/app-release.apk

OPPO 弹「安装增强防护」时，在手机上点右上角「⋮」→「开始深度扫描」→ 继续安装。这一步要手动。

不扫码配对：mooring remote --pair --relay https://<中继地址> --name 名字 --role full 拿到链接，用 adb shell am start -d 发给手机。链接里有密钥，不要打印或发给别人。

真机点按前先用 uiautomator dump 取坐标，列表随时会变。真实测试放在临时目录，用完删掉。
