# Mooring 手机端竞品调研（2026-11-03）

**结论**：Mooring 手机端的方向和同类一致，设计稿在「通知」和「会话控制」两块明显落后。最值得补的是：

1. 人在电脑前时不推送，推送里能直接审批（参照 Paseo、coucou）；
2. 每次允许命令都要验证本人，并留下审批记录（参照 coucou）；
3. 能切换权限模式和模型，审批选项分级（参照 Happy、官方）；
4. 能看具体改动、能发图片（对照表里的六家都能看 diff）；
5. 新任务能选「在新工作树里做」，能从 GitHub 克隆；
6. 配对时在电脑上再确认一次（参照 codex-relay）；
7. 外观照 T3 Code 的克制写法重做（见下）；
8. 收件箱能把事情标为「已处理」或「稍后提醒」，断网时写的话进「未发送」（参照 T3 Code）。

外观上，Mooring 设计稿和主流做法有四点相反：用卡片而不是平铺的行、Agent 回复放在气泡里、自己的消息用饱和蓝色、输入框只是一行。已经参照 T3 Code 重画了一套新外观，见设计稿最上面的「新外观」一节，并和 T3 Code、coucou 的截图并排对照。

要保留的差异点有两个：端到端加密（查过官方文档和 Omnara 在 HN 上的回复，两家都没有），以及逐层浏览目录（查过 Happy 新会话的源码，只有最近目录和手动输入；Paseo 未核实）。建议不做的：语音助手、锁屏实时活动和小组件、多人协作，原因见 02。

## 待你决定

- 8 项里先做哪几项。我建议先做 2、3：主要改 App，后台只多记审批日志，用现有的 `keys`、`send` 就能切模式和模型。第 1 项效果最好，但要先接推送通道（安卓走 FCM 或厂商推送，iPhone 要开发者账号），等你定了推送再做。
- 「建议不做」的三项是否同意。
