# Mooring 手机端：借鉴竞品后要改的地方

依据见 [01-competitor-research.md](01-competitor-research.md)。列 8 项，按「竞品普遍都有、用户每天会碰到」排序。每项写清要改设计稿哪一屏、需要什么后端。

## 1. 通知：人在电脑前就别响，响了能直接处理

- **为什么**：Paseo 按「人在哪」决定推不推送；coucou 在通知上就能允许、拒绝、选答案、回复。Mooring 设计稿只有按事件开关，人坐在电脑前时手机也会一直响；推送点开后还要再点一次才能审批。
- **改设计稿**：
  - 设置页加「电脑前有操作时不推送」，默认开；
  - 通知样式画出来：审批通知带「允许 / 拒绝 / 查看」，问题通知带最多 4 个选项，做完的通知带「回复」。
- **后端**：后台记录工作台最后一次键盘或鼠标操作的时间，3 分钟内有操作就不推；推送内容只带状态和命令指纹，命令原文在手机上解密后再显示（和 coucou 的中转一样只见哈希）。
- **验收**：在电脑前操作时，审批不推到手机；离开 3 分钟后审批能推到手机，并能在锁屏上直接允许。

## 2. 每次允许都验证本人，并留下记录

- **为什么**：coucou 每次「允许」都要 Face ID，而且关不掉；还在本地记录每次决定。Mooring 设计稿只有「打开 App 时验证」，手机解锁状态下被别人拿到就能批 `git push`。
- **改设计稿**：
  - 设置页把「打开时要 Face ID」改成「允许命令前要 Face ID / 指纹」，默认开；
  - 电脑页加一个「审批记录」入口：时间、哪台电脑、哪条命令、允许还是拒绝、在哪台设备上批的。
- **后端**：后台本来就知道每次 `answer` 请求是谁发的，记一条日志就行，现有协议够用。

## 3. 审批分级和会话控制

- **为什么**：Happy 有 4 种允许方式和 5 档权限模式；官方和 ChatGPT 里的 Codex 都能在手机上切模型。Mooring 只有「允许一次 / 会话里都允许 / 拒绝」，也不能切换模式。
- **改设计稿**：
  - 会话详情的标题栏加一个「模式 · 模型」按钮，点开选权限模式（逐个确认 / 自动接受修改 / 只做计划）和模型；
  - 审批详情的选项按 Claude 终端菜单里实际有的项来列，菜单里没有的就不显示。
- **后端**：权限模式在 Claude Code 里是 Shift+Tab 切换，模型用 `/model`，都能用现有的 `keys` 和 `send` 实现；但要知道当前处于哪个模式，需要从终端画面里读出来。

## 4. 看改动和发图片

- **为什么**：对照表里的六家（T3 Code、Happy、Paseo、coucou、codex-relay、Claude 官方）都能在手机上看 diff；官方和 Happy 都能发图片。Mooring 只有一行「改了 1 个文件 +6 −2」，看不到具体改了什么；遇到界面 bug 也没法拍照发给 Agent。
- **改设计稿**：
  - 加一屏「改动」：按文件分组，每个文件可以展开看 diff；从会话里那行摘要点进来；
  - 输入框左边加一个按钮，可以拍照或从相册选图片发给 Agent。
- **后端**：要新增两个操作：一个读工作目录的 `git diff`（只读、限制大小）；一个把图片传到电脑上的临时目录，再把路径作为 `@` 引用发给 Agent。

## 5. 新任务：工作树、克隆和排队

- **为什么**：Happy、Paseo、官方都能让新任务在独立的工作树里跑，避免几个 Agent 改同一份文件；Paseo 还能直接从 GitHub 克隆。Mooring 的目录浏览已经比 Happy 走得远（Happy 只有最近目录加手输），这一点保留。
- **改设计稿**：
  - 新任务页的目录下面加一个开关「在新工作树里做」，选中的是 git 仓库时才显示，默认关；
  - 选择目录页底部「新建文件夹」旁边加「从 GitHub 克隆」；
  - 会话页里 Agent 忙的时候发出的消息显示「排队中」。
- **后端**：`dirs` 操作照 Paseo 的限额来做：默认 30 条、最深 12 层、最多扫 2 万个条目，结果缓存几秒，跳过 gitignore 的目录。启动新任务的 `launch` 操作要能带「新建工作树」参数。

## 6. 配对时在电脑上再确认一次

- **为什么**：codex-relay 配对时，手机显示一个码，要在电脑上确认才算配上。Mooring 现在拿到配对链接就能连，链接被截图转发出去就有风险。
- **改设计稿**：配对页扫码后显示一个 6 位码，提示「在电脑上点确认」。
- **后端**：后台在设备第一次连上时弹窗确认，确认前只放行 `hello`。

## 7. 外观：照 T3 Code 的克制写法重做

- **为什么**：Agent 的长回复不放气泡、自己的消息用中性灰、输入框做成收纳控件的大圆角容器、列表用平铺的行，这四点 T3 Code、codex-relay、Happy 都是这么做的，Mooring 设计稿正好相反。依据见 01 的「外观对比」。
- **改设计稿**：
  - 浅色、深色各出一套，跟随系统。深色沿用桌面端看板的颜色，浅色参照 T3 Code 的中性灰。
  - 首页列表改成平铺的行：项目和机器 → 标题 → 等宽的分支；状态只在右边写一个彩色词。
  - 聊天页：Agent 的回复整宽显示，不放气泡；自己的消息用浅灰气泡；工具过程折成一行「干了 2 分钟 · 跑了 3 个命令 ›」。
  - 输入框改成大圆角卡片：左边是加图片的按钮，中间输入，下面一排小标签（权限模式、模型）；Agent 在跑时发送键变成停止键。
  - 审批照 coucou：命令用大字号，「拒绝」暗红，「允许」带 Face ID 图标，下方写多久后失效。
  - 改动页照 T3 Code：每个文件一张卡片，带「看过」勾选框；底部固定一张汇总卡片。
- **后端**：不需要。字体用 DM Sans 或系统字体，打包进 App。

## 8. 收件箱分组：稍后提醒、已处理、未发送

- **为什么**：T3 Code 的首页除了正常的会话，还有「稍后提醒」「已处理」两组，默认折叠；断网时写的话放在「未发送」，重连后自动发。Mooring 的收件箱只能看，不能把处理完的事挪走，越积越多。
- **改设计稿**：收件箱的行支持左滑「已处理」、右滑「稍后提醒」（1 小时、今晚、明早）；底部是折叠的「稍后提醒 · 2」「已处理 · 5」；断网时发的话进「未发送」。
- **后端**：「已处理」和「稍后提醒」先只存在手机上；断网时的消息由 App 排队，重连后发出。

## 保留的差异点

- **端到端加密**：官方会话记录存在 Anthropic 服务器上，Omnara 自己说没有端到端加密，HN 上有用户把它当成硬门槛。
- 「接上已经在跑的会话」不算差异点：官方在会话里输入 `/remote-control` 就能接上，coucou 也能看和审批。
- **目录逐层浏览**：Happy 的新会话只有最近目录和手动输入。

## 建议不做

- **语音助手**：Happy 和 Omnara 的做法要把内容交给第三方语音服务，和端到端加密冲突。输入框里用系统键盘自带的听写就够了，不单独做。
- **锁屏实时活动、小组件、Siri**：coucou 做得很深，但要 Apple 开发者账号和推送证书，在你决定做 iPhone 推送之前先不做。
- **多人协作、内置浏览器、定时任务**：和「不在电脑前时看住 Agent」这个定位关系不大。

是否采纳由你决定，尤其是「建议不做」的三项。
