# 官方中继怎么开放

## 要定的事

官方中继要不要给没有自建中继的人用。看每月花费、滥用事件数、新用户里用手机远程的比例。

- 预算：每月 100 元以内（用户 11-08 定）。
- 放弃条件：花费超过预算，或出现处理不了的滥用，就退回邀请制或重新关上。

## 现在（11-08）

- 中继开着注册密钥，只有带密钥的电脑能挂上来；手机只能连和它配过对的电脑，内容端到端加密。
- 服务器是腾讯云上海的轻量应用服务器，套餐含流量包。11-04 到 11-08 一个人用，中继进出共约 300 MB，折合每月约 2 GB。
- 手机把中继地址存在每条配对里（`mobile/src/remote/link.ts`），中继换地址后旧配对不会跟过去，要重新配对。

## 第 1 步：邀请制

- 中继：一把共用密钥改成密钥清单，每人一把，带名字和额度，可单独吊销，改清单不用重启。
- 按密钥限每月流量和同时在线的电脑数。
- App：设置里「使用官方中继」，填邀请码。
- 发给 10–20 人，跑 2–4 周。成本在预算内、没有滥用，再进第 2 步。

## 第 2 步：公开

- App 第一次打开时自动领一把低额度密钥，按 IP 限领取频率，必要时加 GitHub 登录。
- 写清中继能看到什么（IP、连接时间、流量大小）、看不到什么（内容）。
- 腾讯云设带宽或流量上限，防账单失控；用户多了再考虑国内外各一台。

## 第二台：香港（11-26）

- 方案：电脑两台都挂，手机两台一起拨、先通的留下（[决定记录](../decisions/2026-11-26-two-relays.md)）。
- 香港机：Debian 13，1 GB 内存。`fibo-relay` 由 systemd 管理，只监听本机 8787 端口；前面是 Caddy 做 HTTPS，用 Let's Encrypt 短期 IP 证书，Caddy 自己续期，不写访问日志。443 端口已经被同机的代理占用，所以中继走 8443。
- 待用户处理：云平台安全组只放行了 22、80、443，要再放行 TCP 8443（11-26 实测：从国内访问，8443 和其他高位端口全部被丢包）。放行之后，在 Actions secret 里加第二个健康检查地址。

不做：把共用密钥写进 App（等于完全开放，安装包里一扒就有）。

## 告警验收（11-16）

`relay-health.yml` 对当前 IP 入口和将来的域名都可用，不用等 DNS。地址放仓库 secret `RELAY_URL`（日志不打印地址），不放注册密钥。每 6 小时检查一次，证书不足 48 小时或健康接口失败即使工作流失败。GitHub 定时任务可能延迟，不承诺精确到点。

邮件通知依赖操作者的 [Actions 通知设置](https://docs.github.com/en/subscriptions-and-notifications/how-tos/managing-github-actions-notifications)，可选择只收失败；定时运行通知送给最后修改 cron 的用户。工作流通过只能证明探测成功，邮件实际送达需单独确认。
