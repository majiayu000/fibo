# 一台电脑两条路：ssh 和中继自动选，走哪条看得见

状态（2026-11-27）：已做，两个待定问题按默认做（你 11-27 回复「可以」）；实机结果见文末。上一步是 [11-27 的决定](../decisions/2026-11-27-computers-over-relay.md)（PR #638）：电脑已经能只经中继连另一台电脑，但 `machines.json` 里一台机器只能写一条路（`"via": "ssh"` 或 `"relay"`）。

## 为什么做

用户原话：「可以自动选路，可以让用户选择 tailscale 和服务器中继，应该是都支持的」。

两台 Mac 的实测（11-27，agentos → apple，各 100 次）：已开连接上一个来回，ssh 中位 16 ms，中继 139 ms；新开一条连接，ssh 0.03～0.05 s，中继约 0.5 s。中继慢将近 9 倍，只该在 ssh 不通的时候用。同类（Paseo、Pane、t3code）都是一台机器同时挂几条路、按延迟选，界面上标出走的是哪条。

## 成功标准

在 agentos 上看 apple：

1. 两条路都通时走 ssh，机器标题写「3 个会话 · ssh 16 ms」。
2. 在 agentos 上 `tailscale down`，10 秒内标题变成「中继 1xx ms」。窗格重连后内容还在，apple 上的 Agent 会话不受影响。
3. `tailscale up`，60 秒内换回 ssh。
4. 设置里把 apple 改成「只走中继」，标题立刻变，ssh 不再连；改回「自动」，恢复第 1 条的样子。
5. 用旧版 Fibo 打开同一份 `machines.json`，照旧按一条路连上，不报格式错误。

## 用户看到的

- **机器标题**：现在是「N 个会话 · 17 ms」，改成「N 个会话 · ssh 17 ms」或「N 个会话 · 中继 139 ms」。只有一条路的机器也写路线名。鼠标悬停时说另一条路怎样：「中继 139 ms」「中继：没配对」或者「ssh：连不上（原因）」。
- **设置 → 远程机器**：有中继配对的机器，那一行多一个「路线」选项：自动 / 只走 ssh / 只走中继。没有中继配对的机器不显示这个选项。
- **`fibo remote join`**：如果 `machines.json` 里已经有同名的 ssh 机器，就给它加上第二条路，打出「apple 现在有两条路：ssh 和中继，自动选快的」。现在的做法是直接改成只走中继，用户的 ssh 就没了。

## 数据

`machines.json` 里每台机器多一个字段 `auto`：

```json
{ "host": "apple", "via": "ssh", "auto": true }
```

- `via` 的意思不变：只认这个字段的旧版 Fibo 照它走一条路。`auto` 为 true 时，新版两条都连，先通过 Fibo 握手的路线先用，之后按下面的规则换。
- 有没有中继这条路，看 `<config>/relay-links/<host>.link` 在不在。`auto` 为 true 但没有链接文件，就只走 ssh，悬停时说「中继：没配对」。
- 怎么写：`join` 碰到已有的 ssh 机器，保持 `via: ssh`，并设 `auto: true`；`join` 一台新机器，写 `via: relay`，不设 `auto`，因为 ssh 连不连得上不知道，用户可以在设置里打开。设置里的「路线」：自动写 `auto: true`，只走 ssh 或只走中继写对应的 `via`，并去掉 `auto`。
- 旧数据：没有 `auto` 的条目和今天完全一样。#638 之后被 `join` 从 ssh 改成 `relay` 的条目，新版不自动改回来，因为分不清用户是不是故意的；设置里点「自动」就恢复。
- 旧版读新文件：Spec 没有 `deny_unknown_fields`，旧版会忽略 `auto`，按 `via` 走。不新增 `via: "auto"`，因为旧版读到不认识的值会整份 `machines.json` 报格式错误，所有机器都不见了（`machines.rs` 的 `load_from`）。

## 怎么做

只改窗口这一侧，被连的那台不用改。

### 1. 每台机器一个本地分流

现在 `m/<host>/workbench.sock` 由 `ssh -L` 或 `fibo remote dial --listen` 直接监听（`attach.rs` 的 `forward_argv`）。改成：

- 两条路各监听一个旁边的 socket：`m/<host>/ssh.sock`、`m/<host>/relay.sock`。各自的 supervisor 照旧，断了重起，退避最长 30 秒。
- 窗口自己监听 `workbench.sock`。每接一条连接，就连到当前选中的那条路的 socket，两头对拷，每条连接两个线程。连接记下自己走的是哪条路。
- 换路时：之后的新连接走新路，**旧路上的连接由分流这里关掉**。窗口里已有的断线重连会把它们重新连上（PR #638 之前就是这样，`visual_drop_link` 守着）。路断了的时候必须主动关：ssh 那边要等 `ServerAliveInterval=15` × 2 才发现断了，窗格会白白挂 30 秒。

`Host::of`、`ensure`、`hosts.rs`、`attach.rs` 里认 `workbench.sock` 的代码都不用改。

### 2. 两条路分别测延迟

- 现在 `hosts.rs` 的 `round_trip` 在 `workbench.sock` 上复用一条连接测延迟。改成分流模块在 `ssh.sock`、`relay.sock` 上各留一条连接，每 5 秒各测一次，读超时 3 秒。用的是已开的连接，不占中继每分钟新开的名额，只是每台机器在中继上一直占一条会话（每台最多 64 条，`MAX_SESSIONS`）。
- `machines::set_latency` 写当前选中的那条路，另外记下另一条路的结果，给悬停用。

### 3. 选路规则（一个纯函数，单测覆盖）

输入是两条路各自最近几次的测量，以及 `via`、`auto`；输出是走哪条路。

- 启动时：两条路同时问那台是谁（ssh 的 `remote_socket`、中继的 `--about`）。确认 ssh 身份或等到 ssh 的身份查询失败后，工作区才可使用已通过 Fibo 握手的路线。之后按下面的规则判断要不要换。
- 当前这条测一次失败（超时、断开）：如果另一条最近一次测量成功，**马上换**。所以检测加切换最长约 5 + 3 秒，满足 10 秒内。
- 另一条**连续 3 次**比当前快 20% 以上、并且至少快 5 ms，才换过去（门槛取 Pane 的做法）。两条都没有优势时，留在 `via` 那条。
- 只走一条（`auto` 不是 true）时不测另一条，也不起另一条的进程，和今天一样。

### 4. 同一台的核对

两条路连的必须是同一台：ssh 路读到的 `machine-id`（`remote_socket` 那段脚本），要和中继 `About` 里的 `machine` 一样。不一样就不用中继这条，悬停时写「中继：配对的不是这台（重新 join）」。ssh 路读不到 id 时，不核对，直接用（有了中继配对，那台就一定生成过 id，读不到说明那台的 Fibo 太旧）。如果工作区已经在 ssh 离线时经中继打开，后来 ssh 恢复却报出另一个 id，旧工作区的连接会断开。重开窗口进程或重新选择路线后，可使用 ssh 那台机器的工作区。

### 5. 其他

- `Host::run`（在那台跑 `fibo` 命令）：ssh 路通的时候就走 ssh，即使当前选的是中继；只有中继通时才返回现在的说明。
- 代码放在新文件 `crates/fibo-app/src/attach/routes.rs`（分流和选路）。`attach.rs` 只改 `start` 和 `supervise` 的调用；它已经 450 行了，单个文件不能超过 800 行。
- 字符串走 `t!`，英文写进 `locales/en`。

## 验收和守护测试

- 单测：选路函数（启动先通先用；当前失败马上换；滞回要连续 3 次并超过两个门槛；只走一条时不换）；`machines.json` 兼容（没有 `auto` 的旧条目；用一个不带 `auto` 字段的结构体去读带 `auto` 的新文件；`join` 碰到已有 ssh 机器时加上 `auto`）。
- 分流测试：起两个假的旁边 socket，切换后新连接到了新那边，旧连接被关掉；当前那条路的 socket 消失后，新连接自动走另一条。
- 实机：按上面「成功标准」的 1～5 条在 agentos 和 apple 上走一遍，录下标题的变化，并记下切换时窗格从断开到重新出画面的时间。

## 不做（这一步）

- 同网直连、UDP 打洞、一条会话里多路复用（决定里的做法 B）、在窗口里配对电脑：顺序和理由都在 11-27 的决定里。
- 电脑同时拨两台中继：`dial` 已经按配对链接里的中继列表一台台试（`relay/dial.rs` 的 `open`），这一步不动。

## 待你决定（不回答就按默认做）

1. **从中继换回 ssh 时，已开着的窗格要不要马上断开重连？** 默认是马上断开：会闪一下，但之后打字就是 16 ms。另一种做法是只让新连接走 ssh，已开着的窗格留在中继上，直到它自己断开，不会闪，但那些窗格会一直慢。
2. **`join` 碰到同名的 ssh 机器时，默认是加上第二条路（`auto`）**，而不是像现在这样改成只走中继。

## 实机结果（11-27，agentos 看 apple，`auto: true`）

用 `kill -STOP` 停住 agentos 上的 `ssh -L` 进程，模拟网络黑洞（不能真的 `tailscale down`：测试本身就是经 Tailscale 连到 agentos 的）。脚本每秒经 `workbench.sock` 新开一条连接，同时一直开着另一条连接，各测一个来回：

| 时刻 | 新开的连接 | 一直开着的那条 |
|---|---|---|
| 停住 ssh 之前 | 11～15 ms | 10～17 ms |
| 停住后 8 秒内（脚本自己等 4 秒超时，只能精确到这里） | 切到中继，150～230 ms | 被关掉，重连后走中继 |
| 恢复 ssh 后约 10 秒 | 回到 ssh，12～20 ms | 被关掉，重连后走 ssh |

第一次跑的时候用了 18 秒才切过去：探测超时后又新开一条连接重试，打招呼等满 10 秒。改成超时不重试、新连接也只等 3 秒以后，满足 10 秒内。

没验：窗口里标题和悬停文字的样子（从 ssh 进 agentos 截不了屏），设置里点「只走中继」，以及换路时窗格从断开到重新出画面的时间。
