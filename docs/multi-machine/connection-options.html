连接方式：同类产品怎么做，Mooring 怎么选（源码版）

2026-11-04。16 个候选，8 个开源产品读了固定版本的源码；Rex、VS Code、Claude Remote Control 闭源，只有文档。标签：源码 读过源码，文档 只看了文档。正文和每条源码链接在 docs/multi-machine/peerscope/rounds/20261104-s1/01-competitor-research.md。

读完源码，结论变了三处：
  1. 和 Mooring 最像的 Rex（Ghostty 作者的新终端）没有自己的中继：把 Tailscale 直接嵌进服务端，身份就是 Tailscale 账号。「Tailscale」选项应该学它内置，而不是让你自己配 ssh。
  2. 官方中继默认开不开，同类分两派：Happy、RustDesk 默认开；Paseo 新装默认关。
  3. 最该先补的是断线续传：Rex 按「已收到多少字节」补发，不重新要整屏。Mooring 每次都要整屏，这也是打开远程画面慢的原因之一。

1 最像 Mooring 的：Rex

Superlogical（Ghostty 作者 Mitchell Hashimoto 的公司）做的终端，围绕给 AI Agent 用的常驻会话设计：后台持有会话，窗口只是客户端。闭源，公测免费。它的第三方 Linux 兼容服务端 tuxosaurus 也用 libghostty-vt 出整屏快照，和 Mooring 同一个思路。

点做法依据
远程怎么连没有自己的中继。内置 Tailscale 节点（rex server start --tailscale → https://rex.<tailnet>.ts.net）、Tailscale Serve、tailnet 地址、或自带 VPN；明文 HTTP 要 --allow-anonymous，文档警告「每个连接都有完全权限」文档 remote-access
内置 Tailscale服务端用 tsnet 作为一台独立设备加入 tailnet，在 443 用 Tailscale 证书开 HTTPS；被控机不用装 Tailscale兼容实现源码 node.go#L115
谁能连用 WhoIs 查对方的 Tailscale 账号，默认只放这台服务器的主人，带 tag 的设备和别的账号都拒；没有配对码兼容实现源码 node.go#L429
断线输出走单独的数据流；重连时带「已收到多少字节」，8 MiB、60 秒内补发，超出才重新要整屏兼容实现 protocol.md
代价要开 tailnet 的 HTTPS 证书，设备名会进公开的证书透明日志；第三方实测一次调用 0.07–0.09 秒文章 classmethod

tuxosaurus 不是 Superlogical 的代码，它自述按 Rex 服务端的一个版本跑同一套协议测试，只能当兼容实现的证据。

2 各家中继的内部构造

中继形态能看到什么依据
Happy 服务器A：数据库存会话和消息，socket.io内容 AES-256-GCM 加密；会话 id、tag、在线状态、时间戳明文源码 schema.prisma
sshx 服务器A：转发加密终端流密钥只在链接 # 后面，服务器拿不到源码 controller.rs
Paseo 中继B：Cloudflare WorkerNoise_NK，daemon 公钥放链接 # 后面源码 secure-channel.ts
Tailscale DERPB：按目标公钥转包只有「目标公钥 + WireGuard 密文」源码 derp.go
iroh-relayB：按 EndpointId 转发IP、EndpointId、字节数；TLS 绑定对端公钥源码 verifier.rs
Syncthing strelaysrvB：拼接IP、谁找谁、字节数（还会公开在状态页）；两端 TLS源码 session.go
RustDesk hbbs + hbbrB：hbbs 签公钥、帮打洞，hbbr 转字节验签失败会退回明文源码 client.rs#L1689
upterm uptermdSSH 中间人能读到内容源码 sshstock.go
Mooring mooring-relayB：WebSocket 转发Noise 端到端；IP、路由码哈希、时间、字节数本仓库

3 默认值、换路

产品默认连上后还会换到更好的路吗
Happy官方 api.cluster-fluster.com，手机和 CLI 都是不直连，永远经服务器
RustDesk官方 rs-ny.rustdesk.com；TCP/UDP/IPv6/WebRTC 同时打洞源码里没找到中途换路
Paseo新装中继默认关，只听本机；开了才走 relay.paseo.sh没找到自动切换
Syncthing公共中继池默认开会：局域网 TCP > QUIC > 公网 > 中继，有更好的就换
iroh4 个区域官方中继会：每 60 秒检查，同一连接里换路不断线
Tailscale直连优先，DERP 兜底会：有流量时每 3 秒心跳，已直连也每分钟再试
Rex没有服务器，默认只听本机交给 Tailscale

第一版只看文档时写错的：Paseo「首次启动会问」→ 实际新装默认关；sshx「不能自建」→ 代码里有 --server；upterm「没写」→ 能读内容；RustDesk「一律加密」→ 有明文退路；iroh「约九成能直连」→ 只是文档说法，源码里没有。

5 要做的事，按顺序

#事学谁大小
1显示走哪条路、一个来回多久sshx小
2断线续传：按已收到的字节补发，不重新要整屏；打开时先显示上次画面Rex中
3桌面连桌面也能走中继（多机第 5 步）—中
4Tailscale 内置：tsnet 作为独立设备，按账号放行（Go 库，要做可行性试验）Rex中到大
5走中继时每分钟试一次直连地址，通了就换Syncthing、Tailscale小
6官方中继：部署 mooring-relay（机房、域名、限速、费用先定；不加账号）Happy、Paseo要你授权和机器
7自建中继说明：一条 docker run + 两个设置RustDesk、upterm小

不建议做：自己写打洞（用 Tailscale 或 iroh）；中继退回明文或解开内容（RustDesk、upterm 的反面例子）；另做账号体系。
