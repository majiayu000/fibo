连接方式：同类产品怎么做，Mooring 怎么选

2026-11-04。15 个候选，深挖 8 个，全部只读了官方文档和 README，没装上实测。正文和事实核验在 docs/multi-machine/peerscope/rounds/20261104-s1/。

结论：自己有服务器的同类产品，常见做法是「官方服务器默认、设置里能换成自建、能直连就不走服务器」，RustDesk、Syncthing、iroh 三点都写明了；抽查的 5 家都写明中继看不到内容。
Mooring 建议一个「连接方式」设置，四个选项：自动（默认）、官方中继、自建中继、只走 ssh/Tailscale。
最先做的是显示当前走哪条路、一个来回多久——今天 apple 那条 Tailscale 路 400 ms，界面上看不出来。

4 要做的事，按顺序

#事大小
1显示当前走哪条路、一个来回多久（参照 sshx 的延迟估计）小，马上能做
2桌面连桌面也能走中继（多机第 5 步），复用第 4 阶段的设备配对中
3「自动」：先试已知的局域网 / Tailscale 地址；以后可换 iroh 打洞简单版小，iroh 版大
4官方中继：部署 mooring-relay（机房、域名、限速、带宽费用要先定；不加账号）要你授权和机器
5自建中继说明：一条 docker run + 设置里填两个值小

不建议做：自建 Tailscale DERP/Headscale（那是 Tailscale 的事）；账号体系（配对码 + 路由码已够，这比 VS Code、Claude 都轻）。

5 待你决定

  • 默认是不是「自动」。
  • 直连不通时默认就走官方中继，还是像 Paseo 那样第一次先问你——前者省事，后者不会在你不知情时把流量交给第三方服务器。
  • 官方中继放在哪（国内节点？）、什么域名、谁出机器。
  • 直连先做简单版（试已知地址），还是做打洞：iroh、把 Tailscale 嵌进 App、局域网 mDNS 发现，还没比较。
