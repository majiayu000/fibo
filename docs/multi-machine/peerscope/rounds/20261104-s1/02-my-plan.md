# Mooring 的连接方式：怎么设计（2026-11-04）

要支撑的决定：Mooring 给用户哪几种连接方式、默认哪个、在哪里选、各自要做多少事。
放弃条件：官方服务器两周内拿不到一台机器，就先只做「自动直连 + 自建中继」，官方服务器往后放。

## Mooring 现在有什么

| | 电脑连电脑 | 手机连电脑 |
|---|---|---|
| 走法 | 只有 ssh（用户自己保证 ssh 能连，比如 Tailscale） | 只有自建中继（`mooring-relay`），配对链接里带中继地址 |
| 加密 | ssh | Noise 端到端，中继看不到内容；每台手机独立路由码（第 4 阶段） |
| 直连 | 取决于 ssh 走哪条路 | 没有，一律经中继 |
| 官方服务器 | 没有 | 没有部署 |

## 建议：一个设置项，四个选项

设置 › 手机与远程 ›「连接方式」，每台机器、每台手机可以单独改：

| 选项 | 做什么 | 给谁 | 参照 |
|---|---|---|---|
| **自动（默认）** | 先试直连（局域网地址、Tailscale 地址），通了就用；不通走 Mooring 官方中继；走中继期间每分钟再试一次直连 | 大多数人，不用懂网络 | Syncthing、RustDesk |
| **Mooring 官方中继** | 只走官方服务器 | 两台不在一个网络、没装 Tailscale | Happy、upterm |
| **自建中继** | 填中继地址（和可选的注册 key），其余同上 | 不想经过任何第三方的人、公司 | RustDesk 的「ID 服务器 / Key」、Happy 的「Server URL」 |
| **只走 ssh / Tailscale** | 现在的方式：`ssh 主机` | 已经有 Tailscale 或局域网的人 | Paseo 的「拒绝中继」、VS Code Remote-SSH |

每个选项旁边都写明谁能看到什么，照 Syncthing 的写法。按 `mooring-relay` 现在的实现，中继只存路由码的 sha256，转发的是 Noise 加密后的字节，所以官方中继写：「看不到内容；能看到两端的 IP、路由码的哈希、连接时间和流量大小」。

手机若改成直连，电脑就要开一个监听端口，多一个能被扫到的入口；所以手机默认只走中继，直连只在局域网 / Tailscale 地址上开。

## 要做的事，按顺序

1. **显示实际走的是哪条路、一个来回多久**（参照 sshx）：侧栏机器标题写「Tailscale · 400 ms」或「官方中继 · 60 ms」。改动小，今天就能做；今天卡住的 400 ms 本来就该一眼看到。
2. **桌面连桌面也能走中继**（多机第 5 步）：第 4 阶段做完了，桌面之间也用「设备 + 路由码」配对。现在 ssh 那条路跑的就是 `mooring remote --stdio`，和手机经中继说的是同一套远程协议（`crates/mooring-remote`），只是多一种传输方式。
3. **「自动」：直连优先，中继兜底**。两种做法：
   - 简单版：配对时记下对方的局域网地址和 Tailscale 地址，连之前先各试一次，谁快用谁；
   - 完整版的几个候选，还没比较：[iroh](https://github.com/n0-computer/iroh)（Rust、Apache-2.0，文档说约九成网络能直连）；把 Tailscale 嵌进 App（tsnet / libtailscale），给已经在用 Tailscale 的人；纯局域网发现（mDNS），同一网络里零配置。
4. **官方中继服务器**：部署 `mooring-relay`，域名比如 `relay.mooring.dev`，要你授权、准备机器。几个要先定：
   - 机房在哪：国内用户多就要国内节点，否则一个来回一两百毫秒；
   - 限速和名额（iroh 的公共中继就是限速、只给开发用）；
   - 费用：中继只转加密字节，带宽是主要成本；
   - 有没有账号：现在靠配对码和路由码，不需要账号。这是比 VS Code、Claude 更轻的地方，建议保持。
5. **自建中继的说明页**：一条 `docker run` 加上填进设置的两个值，照 RustDesk 和 upterm 的写法。

## 不建议做

- 自建 Tailscale DERP 或 Headscale：那是 Tailscale 的事，Mooring 只需要能走 Tailscale 地址。
- 账号体系：官方中继用配对码 + 路由码就够了，不需要登录。

## 待你决定

1. 默认是不是「自动」（直连优先、官方中继兜底）。
2. 直连不通时，是**默认就走官方中继**，还是像 Paseo 那样**第一次先问你**要不要开中继——前者省事，后者不会在你不知情时把流量发给第三方服务器。
3. 官方中继部署在哪、用什么域名、谁出机器。
4. 「自动」先做简单版（试已知地址），还是直接做打洞（iroh / 嵌入 Tailscale / mDNS 先比较）。
