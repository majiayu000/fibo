远程画面打开要等一秒多：为什么，怎么改

2026-11-04 实测。「正在恢复终端…」的意思是：偷看窗已经打开，正在等那台电脑把这个终端当前的整屏画面发过来；画面到了才显示。这句话是给本机「后台重启后重新接上终端」写的，用在远程上不准确。

慢在哪：网络，不在 Mooring

经 ssh 到 apple 的一个来回现在是 385–829 ms（中位 398 ms），打开画面要三个来回左右，所以一秒多。今天凌晨测按键回显时同一条路是 15–46 ms。

每格约 400 ms；绿色那一点是两台电脑实际干活的时间。

  • ssh 里的 apple 指向 100.113.31.23，是 Tailscale 地址，现在这条路每个来回约 400 ms，像是没走直连、在绕中转。
  • 直接 ping apple 显示 0.3 ms 是假象：解析出来的 198.18.8.125 是 Clash fake-ip 网段，回包的是本机 Clash，不是 apple。
  • 所以先要查的是网络：Tailscale 为什么不直连（tailscale ping 看是不是 DERP），以及 Clash 的 TUN 有没有把 100.64.0.0/10 也接过去绕了代理。这一步我没改你的网络和 ssh 配置。

App 这边可以怎么改（三个方向）

A 先显示上次的画面，再换成最新的推荐

同一个远程终端第二次打开时，立刻显示上次看到的整屏（变暗、右上角写「12 秒前的画面 · 正在更新」），新画面到了就替换。第一次打开仍要等，但状态行写清在等谁。

B 后台一直接着要你处理的远程终端

侧栏里「要你处理」的远程会话，后台就先接上它的画面，点开就是现成的。代价：每个都占一条流、一直传输出；那台电脑会话多时流量不小。

C 只改说法，标出网络有多慢

不改机制，状态行改成「正在从 apple 取画面… 网络一个来回 400 ms」，慢的时候你知道是网络。最省事，但还是要等。

三个方向都会做的

地方做法
「正在恢复终端…」远程时改成「正在从 <机器> 取画面…」；本机重连仍叫「恢复」。
网络慢的提示侧栏机器标题在来回超过 200 ms 时写「网络慢 · 400 ms」，和「旧版，只能看」放在同一处。
