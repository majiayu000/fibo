# 桌面工作台连远程机器

状态（2026-11-03）：开工。方案原稿写于 11-02，在旧仓库 keepline 的 `specs/extensions/multi-machine.md`，这里是迁来后的现行版本。

## 要支撑的决定

Mooring 能不能把另一台机器上的终端和会话，像本机的一样放进侧栏：看状态、看画面、打字、答审批，之后再加上接管、改尺寸、新开终端和对话卡片。约束有两条：

- 本机宿主的信任模型不变，只认本机当前用户；
- 和手机共用同一套远程协议（`crates/mooring-remote`），不另开一套内部协议。

## 11-03 定下的

- **全部做**，不停在只看。
- **第一台远程机器是另一台 Mac**。开发时用 `ssh localhost` 模拟；验收在真的另一台 Mac 上做。
- **走 A 方案**：App 为每台机器起 `ssh 主机 <mooring 路径> remote --stdio`，说远程协议。不把远端宿主的 Unix socket 转发过来（B 方案会把内部协议变成对外接口）。
- **写操作等第 1 阶段的请求信封**：打字、审批、接管、改尺寸、新开终端都是写操作。按 [plan.md](../plan.md) 第 7 条「每件事只有一个所有者」，请求信封、回执和去重只能有一套，所以先做第 1 阶段，远程协议直接用它，不在远程协议里另写一套。
- **第 4 阶段的协议改动要同时照顾手机和桌面连远程**：独立 token、超时和幂等 id、心跳、事件流重订，两边一起受益。

## 第 1 步的做法

- **连接**：`crates/mooring-app` 新加一个远程机器模块，每台机器一个线程：起 `ssh -T -o BatchMode=yes 主机 <路径> remote --stdio`，用 `mooring-remote` 的请求和回复类型收发；`hello` 之后 `list`，再开 `events` 流，有事件就重新 `list`（150 ms 内合并）。断开后按 1、2、4…30 秒重连。
- **远端路径**：每台机器可以填；不填时依次试 PATH 里的 `mooring`、`~/Applications/Mooring.app` 和 `/Applications/Mooring.app` 里的 `mooring`。
- **侧栏**：本机在最上面；每台远程机器一个分组，标题写机器名和连接状态。行的内容直接用 `list` 回复里算好的值（plan.md 第 7 条：对外数据带上算好的值），不在 App 里重新判断状态。
- **窗格**：点开远程终端，用 `watch` 收整屏和后续输出，喂给现有的终端模拟器，只读；标题栏标出机器名。
- **测试**：连接命令可替换。集成测试不经过 ssh，直接起本地的 `mooring remote --stdio --runtime <临时目录>`；`ssh localhost` 只在本机手动验证时用。

## 放弃条件

- 第 3 步做下来，App 要为本机和远程维护两套终端代码，而且差异越来越大 → 改成本机也走远程协议，只留一套。
- 你两周内没有真正连上一台远程机器用 → 停在第 2 步。

## 没验

- 没跨两台真实机器测过，只测过 `ssh localhost`。
- 远端 `mooring` 和本机版本不一致时的提示，还没设计。

## 结果

### 第 1 步「只看」（2026-11-03）：部分完成，待真机验收

- 代码：
  - `mooring-remote` 加了 Rust 客户端（`client.rs`）：按 id 对回复，按流 id 分发流消息；对方断开时，等着的请求和流都会收到原因，ssh 的报错取自它的 stderr。
  - App 加了远程机器模块（`machines.rs`）：每台机器一个监管线程，负责重连。
  - 远程终端走只读的 `Connection::remote` 和 `Pane::remote`，用浮层预览显示，标题栏写「机器名 · 会话名」，标「只读」，不显示「↗ 打开」和审批按钮。
  - 侧栏底部按机器分组；设置 › 手机与远程 › 其他电脑，可以添加和移除机器。
  - core 加了 `Status::from_key`，远程卡片的状态由它换回状态类型。
- 守卫基线多了一处 `card.title`：读的是远端宿主用 `session_title` 算好的名字，不是原始字段。
- 已验：
  - 单测：客户端 4 个、机器模块 3 个。
  - 集成测试 `the_desktop_client_lists_and_watches_another_machine`：经 `mooring remote --stdio` 连真实后台，能拿到列表，watch 的整屏能还原出终端文字，之后的输出也能跟上。

### 第 2 步「打字和审批」（2026-11-04）：完成，待你在真窗口里用

- 协议：
  - 远程协议新增 `input` 操作，内容是终端模拟器编码好的原始键盘字节（base64，最多 64 KiB），可以带 `request` id，只有「完全控制」权限能用。宿主那边对应 `Request::SendInput`。
  - 打字、按键、原始输入三种写入，挪到了 `host/client/typing.rs`，`client.rs` 降到 749 行。
- 桌面：
  - 连接时在 `hello` 里报自己的 client id。
  - 按 `hello` 返回的 `ops` 决定：能 `input` 的机器，偷看窗不再标「只读」，键盘输入原样发过去；能 `answer` 的机器，「允许一次」「拒绝」按钮也发到那台机器。
  - 远程窗格的输入由一个线程按顺序发送：上一条还在路上时排队的按键，合成下一条一起发，所以打字快时每批只等一个来回。每条都带请求 id。
  - 远程终端不显示「↗ 打开」，因为它不是本机会话。
- 已验：
  - 集成测试 `typed_input_lands_once_even_when_sent_again`：断线后用同一个 id 重发，那一行只出现 1 次；方向键按原样到达；空输入被拒。
  - 按键回显延迟，验收线是 p95 ≤ 200 ms（`key_echo_latency`，ignored 测试）：
    - 本机：p95 0.3 ms。
    - 经 ssh 连真的 apple，各 100 次、跑了 3 轮：p95 分别为 15.1、45.9、18.9 ms，最慢一次 128 ms。
    - 在 apple 上测时，用的是 `/tmp` 下一个隔离的后台和新版 `mooring`，测完已经清掉，apple 自己的 Mooring 没动。
  - 窗口端到端（`scripts/remote-typing-evidence.sh`）：本机再起一个后台当作「另一台电脑」，用假 ssh 连过去。harness 像点侧栏那样打开它的终端，往偷看窗里打一行字，对面收到一次。截图里标题栏没有「只读」，也没有「↗ 打开」。
  - 全部测试通过。
- 没验：
  - 远程审批按钮没有端到端测过：宿主的 `answer` 之前就有测试，窗口改走远程这条路径没有测。
  - 没在你的真窗口里对着 apple 打字：apple 上装的 Mooring 还是旧版，不认 `input`，所以窗口会继续显示「只读」，直到 apple 更新。
- 第 3 步之前，远程窗格不会跟着本机窗格改尺寸，那边终端的大小由那台机器自己的窗口决定。

### 第 3 步「接管和改尺寸」（2026-11-04）：完成，待你在真窗口里用

- 协议：
  - `watch` 可以带 `take: true`，表示以写入方身份接上那台电脑的终端。那台电脑自己的 Mooring 窗格随之变成「只读 · 可明确接管」，在那边点接管就能要回来。
  - 新增 `resize { stream, cols, rows }`，只能改已接管画面的尺寸；只看的画面会被拒。
  - 两者都要「完全控制」权限，`hello` 的 `ops` 里列出 `resize` 就表示支持。
- 桌面：
  - 远程偷看窗和本机的规则一样：只看时不改尺寸；你开始往里打字，就用 `take` 重新接上，之后窗格的尺寸变化通过 `resize` 发过去。
  - 那台电脑不支持接管时，照旧只能看。
  - 打字和改尺寸走同一个发送线程，按顺序发出。
- 已验：
  - 集成测试 `a_taken_terminal_follows_the_remote_panes_size`：只看的画面发 `resize` 被拒；接管后改成 132×40，终端里的程序收到 40 132。
  - 窗口端到端（`scripts/remote-typing-evidence.sh`）：在远程偷看窗里打一行字之后，对面终端从启动时的 100×30 变成 136×48，也就是偷看窗自己的大小。
  - 全部测试通过。
- 没验：
  - 没在那台电脑的真窗口里看过它被接管后的样子。这里没有专门测，靠的是宿主原有的 `takeover`（`reconnect_input_resize_and_takeover_are_real_pty_operations`）。
  - 没在真的 apple 上测过接管。
- 和原计划的差别：远程终端还只在偷看窗里用，放进本机的标签和分屏是第 4 步。

### 第 4 步：完成（2026-11-04），界面按方向 A，待你在真窗口里用

- 远程协议新增三个写操作，都要「完全控制」权限，都可以带 `request`，重发只生效一次：
  - `open { cwd? }`：在那台电脑上开一个 shell，放进新标签。空间按 `cwd` 选，取包含它的最深那个空间；没有就用第一个空间。终端和标签的 id 由请求 id 推出来，所以重发找到的还是第一次开的那个。回复 `{terminal, tab}`。
  - `end { terminal }`：关掉窗格并停掉终端，走 `ClosePane`。
  - `outcome { session, outcome: done|abandoned|open, turn? }`：带上卡片里的 `turn` 时，Agent 已经开始新一轮就拒绝。手机和桌面看不到完整的结局，所以「结局被别人改过」这一条不检查。
- 卡片新增 `turn`（这一轮的标识）和 `outcome`（open、done、deferred、abandoned）。
- 这些写操作放在 `src/remote/writes.rs`，`remote.rs` 现在 764 行。
- 已验：集成测试 `another_desktop_opens_settles_and_ends`：
  - 同一个请求 `open` 两次，回的是同一个终端，也只多了一个；
  - 带过期的 `turn` 标完成被拒，不带 `turn` 时生效；
  - 用户在那台电脑上重新打开会话之后，用同一个 id 重发「完成」，回的是第一次的结果，不会再标一次完成；
  - `end` 发两次，终端只关一次。
- 界面：11-04 选定方向 A，见 `docs/multi-machine/board-directions.html`。
  - 远程会话和本机会话放进同一套五列。放哪一列看那台电脑给的 `outcome`、`status` 和 `needs_you`，本机不重新判断。
  - 列内按同一条规则排：要你处理先放有问题在问的，再按等得久排；其他列最新的在前。为此卡片加了 `updated`（秒）。
  - 卡片标题前标机器名，状态词用那台电脑的。点卡片打开那台电脑的偷看窗。拖到「做完了」或拖回「要你处理」，会带着卡片的 `turn` 发 `outcome`；卡片先挪过去，以那台电脑下一次列表为准，被拒就弹出原因。
  - 断开的机器：留着最后的卡片，变淡并写「断开」，不能拖。
  - 只看某个空间、只看有变化、只看已关闭这些筛选只对本机生效，打开时远程卡片不显示；按 Agent 的筛选两边都生效。
  - 侧栏机器标题右边的「＋」发 `open`，开好后在偷看窗里打开。远程偷看窗标题栏有「关闭终端」，点了先问一句，再发 `end`。
  - 那台电脑的 hello 里没有 open、end、outcome（旧版）：不显示「＋」和「关闭终端」，卡片也不能拖。
  - 代码在 `crates/mooring-app/src/workbench/board/remote.rs`；`board.rs` 的测试挪进了 `board/tests.rs`。
- 已验：`scripts/remote-board-evidence.sh`（本机另起一个后台当作另一台电脑，里面放一个 Codex 会话，已经交了一轮）：PASS。
  - 卡片出现在「要你处理」。
  - 拖到「做完了」后，等 20 秒那台电脑重新列出来，卡片还在「做完了」；那台电脑记下的结局是 Completed。
  - 「＋」开出来的终端在偷看窗里显示了 shell 提示符；「关闭终端」之后偷看窗关上，那台电脑上这个终端变成 Exited，它的标签也没了。

- 没验：拖拽手势本身（证据脚本是直接调用落下之后的那段处理）；拖完点「撤销」（远程卡片的提示不带撤销）；断开时卡片变淡的样子；连真的 apple 跑一遍。

## 先不管这台（2026-11-05）

要支撑的决定：连着另一台电脑但没空管时，它能不能不再打扰。放弃条件：用一周后真的因此漏过重要的事，或总是开了又关，就改成定时静音。

状态只有两个，存在 `machines.json` 的 `quiet` 里，和连接状态相互独立；只有用户的操作能改它。

| 从 | 操作 | 到 | 同时发生 |
|---|---|---|---|
| 在管 | 右键这台的标题、胶囊或竖栏按钮选「先不管这台」；⌘P 搜「先不管」 | 先不管 | 正在只看这台时回到全部；开着的偷看窗留着 |
| 先不管 | 灰字行的「接着管」；右键灰字行或它的会话选「接着管这台」；鸟瞰的「接着管」；⌘P 搜「接着管」 | 在管 | 计数、⌘J、列表和卡片立刻回来；不跳转，不抢焦点 |
| 先不管 | 展开、点开会话、在里面打字或回答审批 | 先不管 | 看不等于接着管 |
| 任一 | 断开、重连、重启 Mooring | 不变 | |
| 任一 | 在设置里移除这台 | 不存在 | 再加回来是在管；设置增删别的机器不改它 |

先不管时，连接状态怎么显示：

| 连接 | 在管 | 先不管 |
|---|---|---|
| 连上 | 正常显示 | 灰字行，数字是在等的个数 |
| 连接中 | 方块呼吸 | 灰字行不变，不呼吸 |
| 断开 | 变淡写「断开」，不计数 | 灰字行不变，数字是它最后列出的；会话点不开，悬停写「现在没连上」 |

- 不计入：右上角「要你处理」、⌘J、侧栏角标、鸟瞰卡片。系统通知和 Dock 角标本来就只算本机。
- 没有例外：它问权限也不提醒，会话只是停在那里等。
- 所有布局共用一条灰字行，没有灰色胶囊和灰色竖栏按钮：只有一种样子，也就不会出现「只看一台先不管的机器」这种状态。这改了对照稿底部的文字说明。
- 灰字行不带折叠动画，点一下瞬间展开。
- 存盘失败时本次仍生效，并提示下次打开不会记得。

验证：`scripts/remote-sidebar-evidence.sh`（三种布局、⌘J、鸟瞰、⌘P 两个方向、看不等于接着管、断开中切换、重启读回）；`machines::tests`（读写、旧文件、设置不覆盖）。

切换时有过渡：一个写着机器名的胶囊在原来的位置和灰字行之间飞 420 ms（从右键的位置起飞，⌘P 从列表顶部起飞；接着管时飞回离开的位置），灰字行随它落地出现并亮 600 ms 后淡回。只有侧栏动，放完不再要帧；系统减弱动态效果时不播。目录布局不是这一列，胶囊不画，只有灰字行亮。原因是用户说的「不然用户不知道去哪里了」。
