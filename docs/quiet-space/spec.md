# 先不管这个空间（2026-11-07）

要支撑的决定：空间多了以后，暂时不做的空间能不能不打扰你，下周回来还能接着聊。放弃条件：用两周后真的因此漏事，或总是开了又关，再考虑定时恢复。

用户原话：「我想把它放到后面去，但是我暂时又不想关闭它……下周还会继续聊天，但是我不想让它出现在在跑、需要你处理这个地方」「先不管的东西会不会丢掉呢？」

状态存在 host（`Workspace::quiet_spaces`，表 `quiet_spaces`），不放 `machines.json`：窗口、菜单栏、手机和另一台电脑看到的是同一份。只有用户操作能改它。

| 从 | 操作 | 到 | 同时发生 |
|---|---|---|---|
| 在管 | 右键空间选「先不管这个空间」；⌘P 搜「先不管」或空间名 | 先不管 | 里面有在跑的会话时，右键要按第二下确认，文案写明几个会继续跑；正在看这个空间时切到下一个在管的空间 |
| 先不管 | 灰字行、提示条或鸟瞰的「接着管」；右键灰字行；⌘P | 在管 | 计数和卡片立刻回来；不跳转，不补发通知 |
| 先不管 | 展开、点开会话、打字、回答审批 | 先不管 | 看不等于接着管，面板上方有提示条和「接着管」 |
| 任一 | 重启窗口或 host | 不变 | |
| 在管 | 只剩这一个在管的空间 | 不可操作 | 菜单项变灰；host 也拒绝 |
| 先不管 | 删除空间 | 不存在 | 删除规则不变：有没收尾的待办就拒绝 |
| 在管 | 删除它后其余都先不管 | 不可操作 | 先接着管一个别的空间 |

## 不会丢什么

只加一个标记。空间、标签、终端、会话和待办都不删，进程不停。host 重启造成的进程中断和没有先不管时相同，会话仍列在灰字行里，可以回去恢复。

## 先不管时

- 不算：「要你处理」、⌘J、侧栏、状态栏、菜单栏、系统通知和声音、鸟瞰卡片和待办。判断只在 core：`status::needs_you`、`status_group::column`、`open_todos`、`unfinished_todos`；窗口的列表和计数走 `session_hidden_in`。
- 没有例外：Agent 问权限也不提醒。
- 灰字行写「工作 · 先不管 · 1 个在等」，数的是 `status::asks_for_you`。不超过两个空间时各一行，更多时合成一行「先不管 · 5 个空间」，展开再看：你的空间多，底部不能被占满。
- ⌘P 搜索仍能找到里面的会话，但空查询的最近列表不列。
- 手机和另一台电脑的 `list` 不含这些空间。旧手机不用升级，也回不去：要接着管得在这台电脑上操作。
- `mooring todo list` 仍列出它的待办：Agent 记新待办前要查重。

## 接着管时状态对不对

先不管只是一层遮罩，不改状态：`status::of` 不读它，host 也没有任何写状态的逻辑读它。Agent 在后台照常结束、提问、出错，状态照常走。接着管后每个会话的状态、「要你处理」和鸟瞰列，都和从没先不管时一样（`coming_back_gives_the_state_it_would_have_had_anyway` 对每个样例状态、9 种期间事件、当下 / 4 天后 / 8 天后逐项对比）。

几件容易误会的事：

- 活着的终端不会因为放得久变成「很久没动」：上一轮结束就一直是等你验收。终端已经结束的会话超过 `stale_days`（默认 3 天）会变成「很久没动」，不进「要你处理」，和没先不管时相同。
- 期间提过的问题接着管时只回到计数，不补通知；接着管之后的新事件照常通知。正好和接着管在同一次刷新里发生的新事件也不弹，但计数里有。
- 先不管时会清掉「只看这个空间」的筛选，接着管不会把列表又收窄。

已知的边角：会话归哪个空间只看 `session_space`。会话挂在先不管空间的待办上，却开在另一个空间的标签里，它也算先不管，也不计数；标签里的窗格本身照常显示状态。Agent 换到另一个有自己空间的目录时，会话会跟着换空间，先不管与否也随之变化。

## 没做

- 定时恢复：放弃条件触发后再说。
- 在手机或另一台电脑上先不管、接着管。

验证：`scripts/quiet-space-evidence.sh`（真 host、真鼠标事件点右键菜单和确认、鸟瞰、看不等于接着管、⌘P、接着管、重启读回）；`crates/mooring-core/tests/quiet_space.rs`；`store::tests`、`remote::list::tests`、`desktop::tests` 里的 `a_space_put_aside_*`。
