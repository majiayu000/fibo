# 先不管这个空间：状态机（2026-11-07）

要支撑的决定：空间多了以后，暂时不做的空间能不能不打扰你，下周回来还能接着聊。放弃条件：用两周后真的因此漏事，或总是开了又关，再考虑定时恢复。

用户原话：「我想把它放到后面去，但是我暂时又不想关闭它……下周还会继续聊天，但是我不想让它出现在在跑、需要你处理这个地方」「先不管的东西会不会丢掉呢？」「后面点了管之后，那些状态回复的会是对的吗」「这个状态机要做的非常的有逻辑」。

## 五条规则

下面每张表都能由这五条推出来。遇到表里没有的情况，也按这五条判断，判断不了就是缺规则，要回来补。

1. **空间只有两个状态**：在管、先不管。存在 host（`Workspace::quiet_spaces`，表 `quiet_spaces`），窗口、菜单栏、手机读同一份。
2. **遮罩不改状态**：会话有两层。真实状态（`status::of`：在跑、等你回答……）永远照常走，不读「先不管」；遮罩只决定外面算不算它。接着管时不用恢复任何东西，因为什么都没改过。
3. **算不算被遮罩，看它开在哪个标签**：`session_home` 先看所在标签的空间，没有标签才看列在哪（`session_space`）。眼前的东西不能因为归档位置不同而不提醒。
4. **里面照实显示，外面不算**：进到先不管的空间，窗格和标签照常显示真实状态；侧栏、计数、鸟瞰、通知都不算它。
5. **只加标记**：不删空间、标签、终端、会话、待办，不停进程。

## 空间状态怎么变

| 从 | 事件 | 到 | 同时发生 |
|---|---|---|---|
| 在管 | 右键空间选「先不管这个空间」，或 ⌘P | 先不管 | 里面有在跑的会话时，右键要按第二下确认，并写明几个会继续跑；清掉「只看这个空间」的筛选；正在看它时切到下一个在管的空间 |
| 在管 | 同上，但它是最后一个在管的空间 | 在管 | 菜单项变灰，host 也拒绝 |
| 先不管 | 灰字行、提示条、鸟瞰的「接着管」；右键灰字行；⌘P | 在管 | 计数和卡片立刻回来；不跳转、不恢复筛选、不补发通知 |
| 先不管 | 展开灰字行、点开会话、切标签、打字、回答审批 | 先不管 | **待定，见文末** |
| 先不管 | 在里面新开标签或 Agent | 先不管 | **待定，见文末** |
| 任一 | 窗口重启、host 重启、电脑重启 | 不变 | 启动时打开第一个在管的空间 |
| 先不管 | 删除空间 | 不存在 | 有没收尾的待办时照旧拒绝 |
| 在管 | 删除，且其余都先不管 | 在管 | 拒绝：先接着管一个别的 |
| 任一 | 改名、换目录 | 不变 | |
| 任一 | 手机或另一台电脑 | 不变 | 它们不能改这个状态 |

host 连不上时编辑会失败：状态不变、显示错误。切空间的跳转已经发生，不撤回。

## 真实状态怎么走（先不管期间）

和在管时完全一样。接着管后的结果：

| 期间发生的事 | 接着管后 |
|---|---|
| 在跑的会话结束 | 等你验收，计入要你处理 |
| Agent 提问 / 出错 | 等你回答 / 出错了，计入要你处理 |
| 什么都没发生，终端还活着，放多久都一样 | 原来的状态。活着的终端不会变成「很久没动」 |
| 终端已结束（比如电脑重启），超过 `stale_days`（默认 3 天） | 很久没动，不计入要你处理，会话还能恢复 |
| 标了完成 / 放弃 | 仍是完成 / 放弃 |
| 「稍后再看」到期 | 回到待处理 |

## 每个地方算不算

| 地方 | 先不管时 | 依据 |
|---|---|---|
| 要你处理、⌘J、状态栏、菜单栏、Dock 角标 | 不算 | `status::needs_you` / `session_hidden_in` |
| 系统通知和声音 | 不发；已弹的撤回；接着管不补发，之后的新事件照发 | `desktop::entered`、`left` |
| 通知类插件钩子（如 notify-macos） | 不发；接着管不补发，之后的新事件照发 | `plugin_hooks::changes`、`host::command` 处判断 |
| 鸟瞰卡片、鸟瞰待办 | 不显示，头部有一行灰字和「接着管」 | `status_group::column`、`unfinished_todos` |
| 侧栏列表、空间胶囊、切换菜单 | 不显示，底部灰字行；不超过两个空间时各一行，更多时合成一行 | `session_hidden_in`、`quiet_lines` |
| ⌘P | 搜索能找到会话和「接着管」；空查询的最近列表不列 | `palette/search.rs` |
| 新建待办的默认空间和可选空间 | 不选它；已经在里面的待办可以留着 | `attended_or_first` |
| 手机、另一台电脑的列表 | 不列 | `remote/list.rs` |
| 手机在它的目录里开新终端或恢复会话 | 拒绝，告诉你回电脑接着管（否则一开就从手机上消失） | `remote/writes.rs` |
| `mooring todo list` | 照常列：Agent 记新待办前要查重 | 有意不遮罩 |
| `mooring events` 订阅、`mooring run` 的汇报 | 照常：这是脚本和 Agent 之间的事，不是找你 | 有意不遮罩 |

## 容易误会的边角

- 接着管和某个新事件落在同一次刷新里：不弹通知、不触发钩子，但计数里有。
- 灰字行的「N 个在等」数的是真实状态（`status::asks_for_you`），和接着管后会计入的数一致。
- 会话挂在先不管空间的待办上、开在在管空间的标签里：照常计数和提醒，列表标签仍写待办所在的空间。反过来，开在先不管空间的标签里就被遮罩。
- Agent 切到另一个有自己空间的目录：看标签，不跟着变。
- Agent 用 `mooring todo add` 往先不管的空间记待办：记得进去，鸟瞰不显示，接着管后出现。

## 没做

- 定时恢复：放弃条件触发后再说。
- 在手机或另一台电脑上先不管、接着管。

## 待定：在先不管的空间里继续做事

目前的行为（已实现）：点开、打字、回答审批、新开 Agent 都不改变状态，顶部一直有提示条，新开的东西也不计数。

问题：用户的本来场景就是「下周接着聊」。如果忘了点「接着管」就开始聊，切走后 Agent 问问题也不会提醒，这正好踩中放弃条件里的「漏事」。

| 方案 | 看 | 打字、回答审批 | 新开 Agent 或标签 | 代价 |
|---|---|---|---|---|
| A 现状 | 不变 | 不变 | 不变 | 规则最简单，但会漏事 |
| B 开新才回来 | 不变 | 不变 | 接着管 | 继续聊旧会话仍会漏 |
| C 做事就回来 | 不变 | 接着管 | 接着管 | 回一句话也会让整个空间回来，要再点一次先不管；但只会多提醒，不会漏 |
