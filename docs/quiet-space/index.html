先不管空间 · 状态机

2026-11-07 · 这是这个功能的唯一规格。代码：model/space.rs、workbench/sidebar_machines/quiet_space.rs；证据：scripts/quiet-space-evidence.sh

一句话：先不管是一层遮罩，不是一个新状态。东西都留着、进程照跑，外面不再算它；你在里面开始做事，它就回来。

要支撑的决定：空间多了以后，暂时不做的空间能不能不打扰你，下周回来还能接着聊。放弃条件：用两周后真的因此漏事，或总是开了又关，再考虑定时恢复。

六条规则

后面每张表都能由这六条推出来。遇到表里没有的情况也按这六条判断，判断不了就是缺规则，要回来补。

  1. 空间只有两个状态：在管、先不管。存在 host（Workspace::quiet_spaces），窗口、菜单栏、手机读同一份。
  2. 遮罩不改真实状态：会话的「在跑、等你回答……」永远照常走（status::of 不读遮罩）。接着管时不用恢复任何东西，因为什么都没改过。
  3. 算不算被遮罩，看它开在哪个标签：眼前的东西不会因为归档位置不同而不提醒。没有标签才看它列在哪（session_home）。
  4. 里面照实显示，外面不算：进到先不管的空间，窗格和标签照常显示真实状态；侧栏、计数、鸟瞰、通知都不算它。
  5. 你开始做事，它就回来：打字、回答审批、新开工作，都让整个空间接着管。只是看不算；恢复原有的东西不算；机器和 Agent 做的事不算。宁可多提醒，也不漏事。
  6. 只加标记：不删空间、标签、终端、会话、待办，不停进程。

什么算「开始做事」

你在先不管的空间里结果为什么
键盘打字、输入法、粘贴、Ctrl-C接着管送进程序的是你写的内容
在偷看窗里回答审批接着管你替 Agent 做了决定，它要接着跑
新开标签、分屏、Agent，从待办开始工作接着管新工作
手机在它的目录里开终端或恢复会话接着管否则手机列表不显示，一开就看不见
展开灰字行、点开会话、切标签不变只是看
滚动、选中、复制，鼠标点击和滚轮（含发给程序的鼠标上报）不变全屏程序里滚动也会发按键，分不清就按看算
窗格获得或失去焦点不变这是终端自动发的上报
点开被中断或已关闭的会话（自动恢复它）不变窗格显示出来就会自动恢复，这一步不是你要开工；接下来打字才算
在窗格上标记完成、放弃、稍后再看不变这是收尾，不是开工
Agent 自己：mooring todo add、mooring run、汇报写回不变不是你做的。否则后台一动空间就回来，先不管就没意义了

接着管是整个空间回来，不是单个会话。回一句话后想继续放着，再点一次「先不管」。这是选 C 的代价：只会多提醒，不会漏。

接着管时，会话是什么状态

和从没先不管过时完全一样。真实状态一直在走，只是外面不算：

期间发生的事接着管后
在跑的会话结束等你验收，计入要你处理
Agent 提问 / 出错等你回答 / 出错了，计入要你处理
什么都没发生，终端还活着，放多久都一样原来的状态。活着的终端不会变成「很久没动」
终端已结束（比如电脑重启），超过 stale_days（默认 3 天）很久没动，不计入要你处理，会话还能恢复
标了完成 / 放弃仍是完成 / 放弃
「稍后再看」到期回到待处理

每个地方算不算

地方先不管时依据
要你处理、⌘J、状态栏、菜单栏、Dock 角标不算status::needs_you、session_hidden_in
系统通知和声音不发；已弹的撤回；接着管不补发，之后的新事件照发desktop::entered、left
通知类插件钩子（如 notify-macos）不发；接着管不补发，之后的新事件照发plugin_hooks::changes
鸟瞰卡片、鸟瞰待办不显示，头部一行灰字和「接着管」status_group::column、unfinished_todos
侧栏列表、空间胶囊、切换菜单不显示，一行灰字：「按机器」布局在本机列表末尾，跟本机一起折叠；其他布局在底部，排在先不管的电脑上面。不超过两个空间时各一行，更多时合成一行session_hidden_in、quiet_lines
⌘P搜索能找到会话和「接着管」；空查询的最近列表不列palette/search.rs
新建待办的默认空间和可选空间不选它；已经在里面的待办可以留着attended_or_first
手机、另一台电脑的列表不列remote/list.rs
mooring todo list照常列：Agent 记新待办前要查重有意不遮罩
mooring events 订阅、mooring run 的汇报照常：这是脚本和 Agent 之间的事，不是找你有意不遮罩

容易误会的边角

  • 接着管和某个新事件落在同一次刷新里：不弹通知、不触发钩子，但计数里有。
  • 灰字行的「N 个在等」数的是真实状态（status::asks_for_you），和接着管后会计入的数一致。
  • 会话挂在先不管空间的待办上、开在在管空间的标签里：照常计数和提醒，列表标签仍写待办所在的空间。反过来，开在先不管空间的标签里就被遮罩。
  • Agent 切到另一个有自己空间的目录：看标签，不跟着变。
  • Agent 用 mooring todo add 往先不管的空间记待办：记得进去，鸟瞰不显示，接着管后出现。
  • 窗格自动恢复被中断的会话后，它又开始占资源，但空间仍是先不管，直到你打字。
  • 在别的空间用偷看窗看先不管的会话时没有提示条：提示条属于当前空间。在偷看窗里打字一样会接着管。

没做

  • 定时恢复：放弃条件触发后再说。
  • 在手机或另一台电脑上点「先不管」「接着管」。手机只有「在它的目录里打开」这一条会让它回来。
  • 只让单个会话回来：会多出第三个状态，规则就不再简单。
