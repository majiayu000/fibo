## 阻断与决定

OpenCode 的 TUI 位置参数是项目目录，首条任务应使用 `--prompt`（本机 1.19.5 `--help` 已读回；[官方 CLI 文档](https://opencode.ai/docs/cli/)同样把位置参数列为目录）。现有 remote open 对所有 Agent 都把任务追加成位置参数，因此新建任务和带新指令恢复 OpenCode 都受影响。桌面的延后输入、`fibo run` 等相邻入口不能用来证明这一入口正确。

**决定：不发 RC2，修复后出下一个 RC。** 首条任务、恢复、空任务和带引号/短横线的文本需要回归；旧插件声明应继续使用，不靠更换机器码或重建用户数据解决。

三个测试终端已关闭，并通过 `fibo list --json` 读回确认其 ID 全部消失。证据在 `~/Documents/claude-pages/fibo/2026-11-16-closeout/` 的 `rc2-*-final-screen.txt`、`desktop-interrupt2*`、`before/after-swap-*`、`rc2-cleanup.json`；手机记录在 `~/Documents/claude-pages/mooring/2026-11-16-phone-walk/`。

已验：候选真实换包、终端与 PID 保留、Claude 首轮完成和运行中中断、OpenCode 启动失败现场／没验：手机全表、干净安装及其余桌面项／相邻情况：Codex 尚停在信任目录，OpenCode 恢复路径需随修复复核。

## 阻断后的局部修复验证

新建 OpenCode 任务改成独立的 `--prompt=…` 参数；使用已安装的旧插件声明，真实 CLI 收到原文并返回 `phone-walk-opencode-ready`，Fibo 列表显示等你验收。回归直接运行 shell 并检查 argv，包含引号、换行和以 `-` 开头的任务。Claude/Codex 的图片与位置参数方式保留。

恢复时还有上游限制：OpenCode 1.19.5 的[首页](https://github.com/anomalyco/opencode/blob/v1.19.5/packages/tui/src/routes/home.tsx)消费 `--prompt`，[恢复路由](https://github.com/anomalyco/opencode/blob/v1.19.5/packages/tui/src/app.tsx)直接进入旧会话。实测带 `--session` 的进程有完整 prompt 参数，但旧会话没有收到这条消息。因此恢复时附带消息会在打开终端前明确报错，提示先留空恢复、再从聊天发送；已经打开和已经关闭的会话都走这个检查。没有新增发送队列或更改插件协议。此限制仍保留，不能声称恢复时附带消息已支持。

真实恢复也完成了可用路径验证：空消息恢复后，聊天发送新任务，原会话返回 `phone-walk-opencode-resumed`；带消息恢复在已打开、已关闭两种情况下都明确返回上述错误，没有创建额外终端。三个局部测试终端已关闭，列表读回确认 ID 消失，临时测试目录已清理。证据为 `opencode-launch-native-screen.txt`、`opencode-resume-then-send-screen.txt`、`opencode-resume-final.json` 与 `opencode-launch-cleanup.json`。

这些是修复分支 CLI 对现有后台的局部验证，**不计入 RC2 通过项，也不代替下一候选包的全表验收**。期间另一个会话将用户 Mac App 更新为 `d1a8bf99` build 1231；Android 安装包读回 SHA256 仍为本记录的 `377ff20e…75949`。并发手机走查正在使用设备，本轮没有再换用户 App。
