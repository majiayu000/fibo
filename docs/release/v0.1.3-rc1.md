## 不过

1. **`fibo run` 开出来的会话名是「Claude Code 的旁屏」。** 旁屏标签按发起方的 Agent 起名（`control/open.rs`），这个标签里只有一个会话时，`adopt_tab_name`（`model/workspace_edit.rs`）把这个默认名当成用户起的名，钉到会话上。结果侧栏、手机、`fibo list` 都显示这个名字，不显示任务；从 Claude 里派出去的 OpenCode 会话也叫「Claude Code 的旁屏」。同一个标签里有两个会话时不会钉（第二个 Claude 显示的是它自己起的名「Rc-walk approval file」）。从 v0.1.0 起就有（`28a00643`，11-03），不是 RC1 新引入的。修法要定：旁屏不叫「X 的旁屏」，还是默认名不让会话接走；老会话已经钉上的名字怎么处理。
2. **换 App 不更新已装的插件。** 本机 opencode 插件还是 0.2.2，少了 11-07 加的 `input_hint`，于是 `fibo run opencode` 一直等不到输入框（画面上明明有 `Ask anything…`）。升级上来的用户都会碰到；全新安装带的是新版，碰不到。

## 小毛病

1. 后台 shell 还没看到进程时，`fibo explain` 写「服务，没看过进程」，和 11-07 的决定「不要把进程没看过的情况写成服务」冲突。状态本身没判错。
2. Esc 中断后状态是中断，审批被拒后是等你验收。两次 Claude 画面上都是「Interrupted · What should Claude do instead?」。两边该不该一样，待定。
3. Codex、OpenCode 停在「信任目录」提示时，`fibo run` 放弃交任务。点完信任后，`fibo prompt` 认不出还没开始对话的 Codex（报「没有可识别的 Agent 对话」），只能 `fibo send --enter`；Claude 在同样情况下能认出来。
4. OpenCode 1.19.5 被开在大约 20 列宽的第四块分屏里，启动时段错误；在宽标签里正常。没在 Fibo 之外单独复现窄宽度，所以没证实就是宽度引起的。

## 决定

**待验证**：不发。不过 1 可以先定修法再出 RC2；不过 2 要先定「换 App 时更新附带插件」怎么做，才能说升级路径验过了。手机、干净安装、恢复这三块都没走，等有手机、有公证包时接着走 RC2。
