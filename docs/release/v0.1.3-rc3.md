## 阻断与决定

数目：
- 桌面（隔离后台）：过 26 / 不过 6 / 跳过 2 / 没验 12，另 22 项没走。
- 手机：过 30 / 不过 0 / 跳过 2 / 没验 0。
- 干净安装：没验 6。
- 平台单列：Windows 过 4 / 没验 1，Linux 过 6 / 没验 1，iOS 过 3 / 没验 2。

不过：

1. **阻断** OpenCode：从手机新任务入口（remote open）开的任务，只要带换行或长到折行，对话就一直绑不上。手机上看不到状态、聊天和审批卡。
2. **阻断** OpenCode：留空恢复后，手机聊天发不出去。后台侧亲眼看到，真机上也确认不过（见手机一节的补充确认）。RC2 指给用户的恢复路径在手机上走不通。手机新任务页本来就选不到 OpenCode，所以 ① ② 在手机界面上只能从待办开始走到，或者走协议请求。
3. Codex：remote open 带反引号的任务绑不上。和第 1 条是同一机制，随第 1 条一起修。
4. Codex `st.bgshell`：回合结束后留着的后台任务还在跑，状态却显示等你验收。走查员判不阻断。[11-04 的决定](../decisions/2026-11-04-background-shell-own-client.md)只写了「一条都对不上时算任务」，没写对上一部分的情况（屏幕说 2 个、只对上 1 个），要所有者定。
5. Codex `ap.plan`：「Implement this plan?」开着时显示等你验收，没有计划卡片。不阻断：这个功能从没接入过，兜底规则挡住了手机消息。
6. Codex 31 列信任框：手机卡片上的目录截在折行处，显示的目录和真正被信任的不一样。不阻断：`4eb2ed90` 已登记没修，聊天被挡住了。

第 1、2、3 条是同一个根，在 `recognition.rs`：remote open 起的 Agent 终端在第一句之前不绑对话，而没有回车证据时，要求任务原文在画面上连续出现。OpenCode 行首的「┃」和 Codex 渲染时去掉的反引号，都会把原文打断。恢复时，命令行里其实已经写着 `--session ses_…`。

**决定：不发 RC3。修好第 1–3 条后出 RC4，从头走。**

- 依据：第 1、2 条由走查员判阻断，复核员认可。acceptance 规定走到阻断项就停，修完出下一个候选，从头走。

  - 修复走分支 `fix/remote-open-binding-20261117`，先过一轮独立审查，再开自动合入，合并提交就是 RC4。
