这个 demo 要定什么

决定：鸟瞰里的新待办，要不要从“退出鸟瞰、去左栏输入”改成“待办列里原地输入”。

看什么：切到“新设计”，从鸟瞰连记三条，再开始其中一条。整个过程眼睛不用离开待办列，也不用碰鼠标，才算过关。

放弃条件：如果你觉得输入卡挤占待办列、比现在更打断，或者你其实几乎只在工作区记待办，就不改鸟瞰，只把左栏的入口做好。

定下的规则

  • 在哪点，就在哪输入。工作区里仍然在左栏输入；鸟瞰里连左栏的“新建待办”也打开列内输入卡。
  • 回车不换地方。记下后输入卡还在、光标还在，可以接着写。
  • Esc 一次只退一层。先收起输入卡，再按才回工作区；写了字的草稿留着，不会丢。
  • 待办和会话各管各的。待办是你负责的事，你点完成才结束；会话是一次运行，可以没有待办。一条待办可以连多个会话，也可以一个都没有。
  • 开始后待办不消失。卡片显示“在做 · N 个会话”，点开能进这些会话；会话卡上也写着来自哪条待办。
  • 标完成不停会话。关联会话留在原来的列，各自处理。
  • 记下不等于派活。待办可以是任何事，新建时不问 Agent；要开始时再选 Agent 或普通终端，也可以自己做完点“完成”。
  • 记到哪写清楚。空间默认当前空间，显示在输入卡上；没有合适的就当场新建，只要一个名字。
  • 新卡不能消失。待办还没交给谁，所以按 Agent 筛选时也留着。
  • 空板要说原因。五列全空但筛选项有数时，说明它们都在“很久没动”，给一键显示。

如果要做进 App

  • 鸟瞰的按钮不再调用 show_quick_task（tasks.rs:206 第一行就关鸟瞰），输入卡写进新文件。
  • 输入卡放在虚拟列表之上，和拖拽空位相同（board/column.rs 的 slot），否则滚动和列表重建会丢输入框。
  • 中文输入法选词时的回车不能算保存，这点在真机上要专门验。
  • 现在 status::open_todos 把有会话的待办排除（status.rs:157），要改成只看结局；手机端的待办列表也读这份数据，要一起看。
  • 挂到已有待办可用 core 的 Edit::AssignTask，把会话存成待办已有 Edit::SaveSessionTask；界面入口要核对。
  • 同一件事会有待办卡和会话卡两张，待办列可能变长，真实数据下要再看一次。
  • Task.agent 现在必填，要改成可选或者在鸟瞰里不再显示、不再参与筛选（board.rs:263），旧数据要兼容。
  • “完成”可以用现有的 Outcome::Completed，但现在“做完了”列只放会话，完成的待办会直接消失，要补一种卡片。
  • 选择器（agent_picker）现在只列 Agent，普通终端是新增项；开了普通终端的待办怎么关联，还没想定，demo 里只是留在待办列。
  • N 键在鸟瞰里目前没发现冲突，但没有穷举 keymap，做之前要确认。
