# 手机 App 不再有指纹 / 面容验证

推翻同一天的 [2026-11-28-phone-no-open-lock](2026-11-28-phone-no-open-lock.md)（它去掉了打开时的锁，把批准前的验证留成默认关的开关）。

## Context

#655 合进去后，真机走查时点「允许」又弹出系统验证：这台手机上的开关一直是开的（沿用旧的 `lock` 字段）。用户的话：

> 为什么又出弹窗了？我们不是把弹窗删掉了吗？
> 整个删掉，整个删掉，太烦了。

在这之前用户已经说过「我都想关掉这个设置了，我觉得没有意义呀要不然删掉这个设置算了」。

## Decision

- 删掉手机上的所有指纹 / 面容 / 锁屏密码验证：远程「允许」、信任文件夹、切完全放行、等待面板里提交选择的键都不再验证。
- 删掉设置里的开关和「验证方式」、我的页那一行、审批页「允许要…」的说明、允许按钮上的锁图标。
- 去掉 `expo-local-authentication` 依赖和它的原生插件（iOS 的 Face ID 权限说明随之消失）。
- 保留：危险命令（push、rm、部署这类）允许前的二次确认，开关仍在设置里。

## Consequences

- 旧手机存着的 `lock: true` / `lockWay` 留在本机设置里，没人再读；升级后直接不弹。
- 解锁的手机被别人拿到，能直接批准命令；只剩危险命令的二次确认和电脑端的权限挡着。
- 降级到 11-28 之前的包：那时的 `readSettings` 要求 `lock` 是布尔值。从这一版起新装的手机没有这个字段，降回去会报「安全设置无法读取」，要清 App 数据。

## Verification

```sh
cd mobile && bun test && bun run typecheck && bun run lint
```

`test/auth.test.ts`：存着旧 `lock: true` 的手机点允许，直接发出，不调任何验证。真机：开关原本开着的手机升级后，「允许」「信任」都不弹系统验证。

## Alternatives

- 留开关、默认关（#655 的做法）：开着的人照样被打扰，用户觉得这个功能本身没有意义。
- 只在这台手机上把开关关掉：别的手机上开着的也一样烦，用户要的是整个删掉。

## More Information

重开条件：要做锁屏通知上直接「允许」（手机锁着也能批）时，再看要不要验证。来源：#655、11-05 `d3ac857d`。
