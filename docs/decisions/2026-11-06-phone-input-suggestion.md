# 手机聊天页显示 Claude 的下一句建议，读屏拿，用两周再定去留

## 背景

用户想把 Claude Code 输入框里灰色的下一句建议做进 Mooring。电脑的终端里本来就看得到这行灰字，也能按 Tab 接受；缺的是不在电脑前的时候。

## 决定

只放手机聊天页。后台在手机问的时候读一次屏，输入框里有全暗淡的文字就当建议；点一下填进输入框，发不发由用户决定。手机在「设置」里记下：多少轮结束、多少轮拿到建议、点用了几次。

**两周后按这些数字决定去留。放弃条件：** 拿到建议的轮次里点用不到一成；或者大部分轮次拿不到建议。

## 否掉的

- hook 或日志：2.1.318 没有这个事件，日志里也没有建议。
- `claude -p --prompt-suggestions`：只有 print/SDK 模式才发这条消息，不是用户在用的终端会话。
- 后台在每次输出时读：会给每个终端的输出都加成本。手机问的时候才读，窗口和不看手机的时候都不付这笔。
- 手机轮询时读 `Workspace`，或要等 `chat` 读到 Agent 消息再问：前者是 #110 刚去掉的成本；后者让建议依赖聊天记录是否读全。卡片自带 `turn`，够了。
- 也放进看板卡片、也放电脑窗口：先看手机这一处有没有人用。
- 点一下直接发送：建议是模型猜的，发出去就开始花额度、改代码。

## 已知风险

- **建议不一定出现。** 2.1.318 里，失焦的终端不生成；未使用 20 次后只有每 10 轮生成一次；对话前两轮、plan 模式、上一轮报错、缓存冷都不生成；模型也可能选择不说。实测裸 PTY 约八成出现，Mooring 后台接上客户端时 2 次出现 1 次，没有客户端时 3 次都没有（样本小，这些条件没有逐项拆开）。
- **后台过滤 `CLAUDE_*` 变量。** `CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION` 设在启动 App 的环境里到不了终端；要跳过退避，写进 Claude 的 `settings.json` 的 `env`，或用户 shell 的启动文件。开了要多花额度，所以 Mooring 不替用户打开。
- **读的是画面。** Claude 改了输入框的画法（`❯` 和下面那条线），建议就静默地不再出现，不会报错也不会误报；`agents/claude_suggestion.rs` 的测试里写着 2.1.318 真实的字节。
- 放弃条件里的「拿不到」，有一部分就是上面的退避造成的，看数字时要分开想。
