# 手机 App 打开时不再验证；锁只管批准命令

## Context

11-05 手机第二版照设计稿加了「打开时要 Face ID / 指纹」（默认关）：开着时冷启动和每次切回前台都要验证，远程「允许」、信任文件夹、切完全放行也要验证。11-27 真机上切出去几秒回来就要解锁，Fibo 自己弹的系统验证也会让 App 离开前台、回来再要一次。先试了 60 秒宽限（#655 第一版），用户否了整件事：

> 为什么要打开 APP 的时候验证呢……我一开始以为是手机锁着的时候可以用，结果是在手机解锁之后又加了个锁，这个东西完全没有必要，我从来不需要这种功能，我觉得用户也不会需要。

打开时验证防的是「解锁的手机交给别人，别人看到对话」，系统锁屏已经挡住陌生人；真正要防的是别人拿着你的手机批准命令。

## Decision

- 打开 App、切回前台都不验证，也不遮画面。启动时只等本机设置和待发送消息读出来（读坏了仍然不打开，给「重试读取」）。
- 原开关改叫「批准命令前要指纹 / Face ID」，存储字段仍是 `lock`、默认关。开着时验证：远程「允许」、信任文件夹、切完全放行，以及等待面板里会把选择交给终端的键（选项、回车；↑ ↓ Esc 不验）。

## Consequences

- 以前开着锁的人，升级后不再在打开时被问，只在上面几种操作前被问。
- 多任务界面里能看到对话预览。
- 「手机锁着时也能批准」（锁屏通知上直接允许）是另一件事，要推送，没做。

## Verification

```sh
cd mobile && bun test && bun run typecheck && bun run lint
```

真机：开着开关冷启动、切后台再回来都不弹验证；审批「允许」仍弹。

## Alternatives

- 60 秒宽限（#655 第一版 `f2d460a1`）：给一个不需要的锁打补丁，否掉。
- 去掉所有验证：批准命令前的验证防的是真实风险（解锁的手机被别人拿去批 `git push`），默认关，想要的人自己开。
