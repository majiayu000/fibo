# 手机主页：等你验收排在在跑上面

## Context

手机主页按组往下排。这个顺序已经来回改过两次：

- 4459fca（11-06）真机看过后，把等你验收的折叠行排到在跑上面。
- 7c94c6c（11-07）做新主页时又放回在跑下面，理由是在跑只显示 4 条、推不下去，而且和设计稿一致。

11-08 用户在真手机上问「为什么是在跑的在最上边」。没有审批和出错的时候，在跑就成了第一组；等你验收折成一行，压在 4 条在跑下面，很容易被漏看。

## Decision

主页的顺序是：要你决定（审批、提问、信任文件夹）→ 出错和到点提醒 → **等你验收** → 在跑 → 其他已停下的。

排序依据是「要不要你做事」。在跑不要你做什么，等你验收要你看一眼、标记完成。

不做的事：
- 不把等你验收默认展开。
- 不改在跑的条数上限。
- 不改电脑端看板。

## Consequences

- 等你验收展开后，在跑会被往下推。这是用户自己点开的。
- 设计稿里在跑在上面，这里以本条为准。

## Implementation Plan

- 受影响路径：`mobile/src/app/index.tsx` 里各组的渲染顺序。
- 要避免的写法：按设计稿或者按「在跑要看进度」再把两组调换回去。

## Alternatives

- 在跑放上面（7c94c6c）：否定，理由见 Context。
- 等你验收放最顶上：否定（4459fca 已否）。出错和到点提醒比它急。
