# 不用鼠标也能走遍窗口：区域焦点和键盘光标

状态：方案，待用户拍板，未改代码。对应 [#611](https://github.com/majiayu000/fibo/issues/611)（11-26 窗口层审查，汇总在 #621）。

## 要支撑的决定

- 只用键盘能不能到达窗口里的每个可操作的东西（侧栏的会话行、看板卡片、状态栏、设置里的开关）；用什么键在区域之间、区域之内移动；焦点在哪里怎么画出来。
- 硬约束：焦点在终端里时，Tab 必须照常进终端（shell 补全、Agent 的输入框都靠它）。
- 指标：开着 macOS「键盘导航」的用户不碰鼠标能切换设置、打开会话、在侧栏和看板之间移动，并且一直看得见焦点在哪。

## 现状（2026-11-28，main fc4c954b）

- 窗口里没有一处用 `tab_index`、`tab_stop`、`tab_group`；`track_focus` 只用在输入框和几个大容器上（设置面板、看板区域、窗格、改动面板、诊断等）。
- pinned 的 GPUI 已支持 Tab 导航：`FocusHandle` 的 `tab_index`、`tab_stop`（`window.rs`），`Window::focus_next` / `focus_prev` 按渲染帧里的 tab stop 排序（`tab_stop.rs`），示例 `examples/a11y.rs` 把 tab 绑到 `focus_next`。前提是每个能被 Tab 到的元素都有自己的 `FocusHandle`。
- Fibo 的共享按钮（`ui/widgets.rs` 的 `button`、`icon_button`）是无状态的 `div`，没有 `FocusHandle`；非测试代码里约 417 处 `.on_click`。
- 已有两种「区域拿焦点 + 键盘移动」的做法：
  - 看板区域（`render/main_area.rs`）：区域有自己的 `focus`，抽屉里用 j / k 或方向键走一列。
  - 菜单栏弹出列表（`native.m` 的 `KLRow`）：上下键移动、回车打开。
- 设置面板（`settings/panel.rs`）拿到焦点后拦下全部按键，不往后面的终端漏；但面板里的开关没有一个能用键盘到达。
- 键位（`keymap.rs`）：切标签用 ⌘⇧[ / ⌘⇧]，切窗格用 ⌘[ / ⌘] 和 ⌘⌥方向键，⌘P、⌘J、⌘B 等；⌃Tab 没有被占用。

## 可选方案

### A 每个控件一个 FocusHandle，全部交给 GPUI 的 Tab 顺序

- 按钮、开关、侧栏行、卡片都改成持有 `FocusHandle`，设 `tab_index`，Tab / ⇧Tab 在整个窗口里走。
- 问题：无状态 helper 要改成由所属视图按 id 管一张 handle 表，涉及几百处；侧栏行、卡片会随数据增减，handle 的生命周期要跟着管；几百个 tab stop 用 Tab 一个个走也不好用。

### B 区域拿焦点，区域里一个键盘光标（推荐）

- 区域：侧栏、主区（窗格或看板）、标签栏、状态栏，以及打开时的设置面板、⌘P 面板。⌃Tab / ⌃⇧Tab 在区域之间循环；焦点在终端里时，⌃Tab 也被窗口截下（macOS 惯例：在文本区里用 ⌃Tab 跳出来）。
- 区域之内（终端除外），Tab / ⇧Tab 或方向键移动光标，回车或空格执行，Esc 回到上一个区域。每个区域只要一个 `FocusHandle` 和一个光标位置，沿用看板抽屉和菜单栏列表已有的做法。
- 设置面板里 Tab 在开关之间走，正好接上它已经在拦按键的那段代码。
- 光标画成一圈焦点框：用主题里新加的 `focus_ring` token，深浅两套主题都要看得见。
- 读屏：光标移到的元素带 role 和 label（和 #610 一起做），VoiceOver 才念得出来。

### C 只做设置面板

- 改动最小，只解决「设置里的开关到不了」，侧栏和看板照旧。

## 推荐

B。分步，每步一个 PR：

1. 区域循环：⌃Tab / ⌃⇧Tab 在侧栏、主区、状态栏之间切换，加焦点框。终端获得焦点时 Tab 照旧进终端（加测试守住）。
2. 设置面板：Tab 在开关之间走，空格切换，回车执行按钮。
3. 侧栏和看板：方向键移动光标，回车打开会话或卡片（看板沿用抽屉的 j / k）。
4. 状态栏和标签栏：左右移动，回车执行。

## 接口和改动的文件（预估）

- `crates/fibo-app/src/keymap.rs`：新动作「下一个区域」「上一个区域」，默认 ⌃Tab / ⌃⇧Tab，可在设置里改键（和现有键位一样）。
- 区域焦点和光标：新文件（例如 `workbench/keyboard_focus.rs`），侧栏、状态栏、标签栏各加一个 `FocusHandle`。
- 主题：`ui/theme.rs` 加 `focus_ring` token；`ui/theme_tests.rs` 检查它在深浅两套主题下和背景的对比度至少 3:1（WCAG 1.4.11）。
- 设置面板：`workbench/settings/panel.rs` 的按键处理里加 Tab 移动。
- 守卫：GPUI 测试（visual-test 下，见 #613）验证 ⌃Tab 循环和「终端里 Tab 不被截」；原生场景截图看焦点框。

## 验收标准

- 只用键盘：从终端 ⌃Tab 到侧栏，方向键选中一个会话，回车打开；⌃Tab 到状态栏，打开设置，Tab 走到某个开关，空格切换。
- 焦点在终端里时，Tab 仍然进终端（shell 补全照常）。
- 焦点框在深浅两套主题下都看得见。
- 鼠标操作和现有快捷键不受影响（perf-gate 不退化；侧栏的视图不因光标多出每帧重画）。

## 放弃条件

- ⌃Tab 和用户常用的终端程序冲突（例如某个 TUI 用 ⌃Tab）而且无法改键时，改用别的组合键，方案不变。

## 不做

- 每个控件一个 FocusHandle 的全窗口 Tab 顺序（方案 A）。
- 读出终端里的文字（属于 #610 的第二步）。

## 要你拍板的问题

1. 区域切换键用 ⌃Tab / ⌃⇧Tab（推荐，macOS 惯例），还是 F6 一类？
2. 焦点框只在用键盘时显示（点鼠标不显示），还是一直显示？
3. 先做哪个区域：推荐先做区域循环加设置面板（第 1、2 步），因为设置里的开关现在完全到不了。
