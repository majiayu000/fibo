# 撤销这一轮

状态：方案，待用户拍板，未改代码。对应 [#603](https://github.com/majiayu000/fibo/issues/603)（11-26 竞品对照，汇总在 #621）。

## 要支撑的决定

- 一轮改坏了，能不能在「看改动」里一步把这一轮 Agent 改的文件还原；还原依据什么（会话记录还是 git 快照）；之后又被改过的文件怎么办；还原之后要不要告诉 Agent。
- 指标：Agent 一轮改了几个文件，一次操作回到轮前；其间人改过的文件不会被冲掉。

## 现状（2026-11-28，main 3075da01）

- 记录里已有每次编辑的内容（`crates/fibo-host/src/agents/turn_edits.rs`）：
  - Claude：`toolUseResult` 里新建文件的全文（`type` 为 `create`，`content`），编辑的 `structuredPatch` hunk。
  - Codex：完成的 `FileChange`，`add` 带全文，`update` 带 unified diff。
- `fibo_core::turn_diff` 把同一文件的多次编辑合成净改动；行号和已知内容对不上时，说明中途有别的程序写过文件，这时不合成、按次显示（[2026-11-06 决定](../decisions/2026-11-06-turn-changes-from-the-log.md)）。它已有 400 轮随机编辑序列的测试：合成结果必须把原文件变成最终文件。
- 只有 Claude、Codex 有这些内容；其他 Agent 只有行数。命令、脚本改的文件不在记录里。
- 窗口没有任何还原入口；各 CLI 自己的回退只在终端里，做法各不相同。

## 可选方案

### A 反向应用这一轮的净改动（推荐先做）

- 对每个文件：只有当前内容等于这一轮结束时的内容（由净改动推出）才还原。编辑过的文件反向应用；这一轮新建的文件挪进废纸篓。对不上的列为冲突，不动。
- 还原前把每个文件的当前内容存进 runtime（例如 `reverted/<会话>/<轮>/`），面板给「撤回这次还原」。
- 好处：数据现成；非 git 目录也能用；和 11-06「从记录取」一致。
- 局限：只覆盖 Claude、Codex 用编辑工具做的改动，命令改的文件不还原（面板写明）；这一轮之后 Agent 自己又改过的文件会算冲突。

### B 每轮开始时打 git 快照

- 回合开始时 host 跑 `git stash create`（不改工作区）并存成 `refs/fibo/turns/<会话>/<轮>`；还原就是把这一轮改过的路径恢复到快照里的样子。
- 好处：命令、脚本改的也能还原；所有 Agent 都适用。
- 代价：只对 git 仓库；要准确知道回合从什么时候开始（hook 和记录认出开始有延迟，快照晚了，会把这一轮开头的改动算进「之前」）；每轮都写对象，大仓库有成本；ref 要定期清理。

### C 交给 Agent 自己回退

- 面板只放「让它撤销这一轮」，往终端打一句话。不可靠：Agent 可能只撤一部分，或者理解错。

## 推荐

A 先做：读的部分已经有了，补上写回。B 等 A 用起来后，确实需要覆盖命令改动时再议（另开决定）。

## 接口和改动的文件（预估）

- core：`turn_diff` 加两个纯函数：生成反向补丁；判断当前内容是否等于轮末内容。测试沿用现有风格：随机编辑序列正向再反向，必须得到原文。
- host：`Request::RevertTurn { session, turn }`，回复逐个文件的结果（已还原 / 冲突 / 跳过）；写文件用 `fibo_platform::fs::write_atomic`，先备份。
- 窗口：`workbench/layout/changes_panel.rs` 加「还原这一轮」：先列出要还原的文件和冲突，确认后执行；再给「撤回这次还原」。
- 多机：请求发给会话所在那台的 host。

## 验收标准

- Agent 一轮改三个文件，点还原后三个文件回到轮前；其间人手改过的文件列为冲突，内容不变。
- 这一轮新建的文件进了废纸篓；撤回还原后，文件恢复成轮末内容。
- 不是 Claude、Codex 的会话：不出现按钮，或说明「只有行数，不能还原」。
- 记录没读全（只读了尾部、超过 3 秒没读完）时不给还原，避免只还原一半。

## 放弃条件

- 真实会话里冲突太多（例如超过三成文件对不上）：说明 A 不实用，转 B。

## 不做

- 只还原某个 hunk；一次还原多轮。
- Agent 对话本身的回退：交给各 CLI。

## 要你拍板的问题

1. 先做 A（推荐），还是直接做 B？
2. 被还原文件的备份留多久（例如 7 天）？
3. 还原后要不要往该会话发一句话，告诉 Agent「这一轮的改动已撤销」？不说的话，Agent 还以为文件是它改过的样子，下一轮可能在错的前提上接着改。
